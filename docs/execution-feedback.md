# 真实执行反馈

执行过程与最终结论分开。页面只按后台已发生的动作显示步骤，不用计时器推进，不估计百分比，不公开模型草稿或思考。默认仍是模拟模型与固定模拟数据；工具及宿主核验真实执行。

## 信号来源

- `web_api/service.py`：启动本次环境准备前记录 preparing；排队、取消、成功、失败等状态沿用实际任务状态机。
- `task13_runtime/bridge.py`：请求取得预算许可后记录等待响应；结算后记录响应结束，结束不等于响应内容有效。真实 MCP 工具调用前后记录开始、数据返回或失败。
- `task13_runtime/host.py`：收到完整本轮结果后、收集及验证证据前记录 checking；只有原核验成功且结果保存后，任务才能进入 succeeded。
- `task13_runtime/progress.py`：独立的结构化日志，包含轮次、允许的代码/工具名、操作摘要标识和时间；没有问题、提示词、参数、模型文本、凭据和本地路径。按完整换行读取，部分写入留待下次，旧轮次不转发。

宿主在等待实际驱动响应时读取信号，通常有约一秒的采集延迟。前端轮询间隔约 0.9 秒；这两个周期只用于读取状态，不会生成分析进度。特别快的步骤可能在同一次刷新中一起出现。取消过早时，尚未送达服务的步骤不会被补写成成功。

## 保存与恢复

SQLite schema 2 为原 events 表增加 detail / event_key，保留旧行。进度仅在匹配的 job / session / turn 仍为 running 时写入；同一事件去重。取消中和终态拒绝后续进度。删除对话继续真实删除其任务、证据和事件。

`GET /api/jobs/{id}?after_seq=N` 仍先验证所有权。每条事件返回全局递增 seq、绑定 ID、state/progress 类型和允许的详情；at 是服务记录时间。前端按绑定和序号合并，忽略重复及其他轮次的记录，终态停止轮询。刷新读取完整会话；重启保留历史，不恢复执行或重新计费。旧记录没有执行步骤时不补造步骤。

## 交互

等待时显示当前动作及已发生步骤；完成/失败/取消后折叠过程。工具返回数据不等于结论已核验。停止请求发出与后台确认停止分别显示；未完成步骤不标成功。

断线显示“当前显示的是上次收到的记录”，恢复后只重取状态。提交响应丢失时手动重试沿用原会话和幂等标识。切换历史先隐藏旧内容，证据先清空旧载荷并显示读取中；关闭或切换后的迟到响应不得覆盖当前界面。读取失败提供只读重试。

## 验收入口

- `python -B scripts/check_execution_store.py`：迁移、事件绑定、去重、迟到和部分追加。
- `python -B scripts/verify_web.py`：真实工具审计对照、权限、幂等、恢复、取消与超时；支持 WEB_TEST_PORT / WEB_TEST_OUTPUT。
- `node web/browser-execution.mjs`：真实 Chrome，丢失提交确认、断线、延迟响应、证据/历史重试及手机。
- `node web/browser-check.mjs`：五类能力全流程；`--cancel-only` 额外检查停止请求尚未确认及未完成步骤。

本轮验收报告与真实截图位于 `state/ux-stage2/`。

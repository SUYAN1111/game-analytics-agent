# 自由提问与能力边界

本轮目标：以登记数据、工具和证据约束能力，不以示例句子作为产品白名单。保持不调用付费 API、不提交或推送 Git。

## 入口行为

- 确定性本地分流：纯问候、明确通用问题、缺少数据的请求直接返回短提示；不进入执行队列、不创建分析 core、不请求模型，历史可保存且对话继续开放。
- 可识别的本地意图与参数：剧情统计可指定已登记更新范围，预测可指定登记预测范围，分组可指定已有快照或组别，玩法关联可选已有规则中的玩法对。计划编译为实际 DSH/MCP 工具调用，不填预计算数值。
- 模糊范围先澄清，选择只填入输入框，用户确认发送。范围和选择持久保存，刷新后有效；追问只取当前所有者当前会话已成功或待澄清的上下文，旧数据引用不作为本轮证据。
- 本地语法未覆盖的限定条件不丢弃：offline 提示尚未连接语言模型并请用户补充；live 交给现有受限 harness 理解。因此离线规则解析不等于任意自然语言理解。
- 混合因果/通用问题：明确可支持的统计部分实际查询，其余部分单独说明。多个分析方向不明确时先询问方向，不擅自只做其中一种。
- 自选 CSV/Excel 仍仅是预览与字段配置，不进入分析。

## 真实模型协议

产品补充提示见 `web_api/scope_prompt.md`。原证据回答协议保留，新增有限枚举的 clarification/out_of_scope 控制响应，以及包裹原核验回答的 partial 响应。控制提示由宿主固定生成，不允许模型通过提示字段输出未经核验的数字或任意文字；部分回答必须有真实证据。

原工具白名单、权限、模型/工具调用额度、费用预留、超时取消和证据核验继续生效。没有新增通用浏览、代码执行或任意 SQL 权限。当前首步仍由宿主要求 inspect_context；本地已拦截的请求不会进入这个步骤。

## 范围与状态

目录从已登记 host、segmentation/model 和 association 业务/规则资产提取；本地参数只从这个目录选择。页面显示实际计划范围，不偷偷把用户原问题替换成某条示例。

Web 数据库版本 3 新增 routing 表，关联到任务并级联删除；旧记录与原证据保留。clarification / out_of_scope / guidance 是正常对话状态，partial 是有核验结果的部分完成，均与执行失败区分。原文、提交幂等性、所有者检查、取消和重启中断行为保留。

前端对部分回答突出未完成内容，复制/下载保留限制；方法说明继续按实际证据归属。原四阶段记录仍见 `UX_PHASES.md`。

## 验收与剩余边界

`scripts/check_scope_routing.py` 验证本地分流、参数化计划、上下文、控制协议、幂等性和数据库删除。`web/browser-scope.mjs` 验证真实浏览器与工具链、零请求提示、澄清与刷新、范围追问、部分完成、新玩法对和预测范围。报告在 `state/scope-routing/`。

已通过上述合同和端到端检查、真实 harness 的控制响应演练、原五能力与界面回归、真实删除及取消回归。混合请求中的不支持部分不会污染主查询的版本参数；比较统一按时间先后展示，并在页面显示范围。回归曾发现测试入口的全角标点规范化问题，修复后重跑失败/取消及删除检查通过。最终版本和截图记录见 `state/scope-routing/VALIDATION.md`。

真实 DeepSeek 的任意表达理解、工具选择正确率、误拒率与 token 开销仍需单独授权联调。本轮可验证协议和真实工具链，不能证明真实模型达到这些指标。规则、输入长度和固定输出额度不是语义防火墙的完美证明。

# 真实 DeepSeek 首轮验收（2026-09-18）

结论：接通了真实模型，自由提问和部分多轮分析可以完成，但尚未达到可部署的可靠程度。15 个产品案例中 11 个符合预期，4 个不符合预期。其中 4 个为本地零模型请求处理，11 个进入真实模型；真实模型案例 7 个符合预期、4 个不符合预期。小样本单次验收不能解释为总体准确率。

本轮只测试、核对并记录问题，未修改产品业务逻辑来掩盖失败。原四阶段界面工作和冻结分析资产保持。下一步先修复范围绑定和流程可靠性，再回归；不进入云端部署阶段。

## 待修问题（按顺序）

1. **P0：用户范围缺乏硬绑定。** 数据和登记资料只有模拟区域 R1/R2/R3，没有北京对应关系。模型把“北京”自行当作 R1，宿主只校验 R1 数字是否来自证据，没有拒绝无依据的映射。界面摘要又只显示更新名称，未突出 R1。应先核对用户约束与已登记值/别名；不能映射时澄清或拒绝，不能靠提示词或数值核验代替范围校验。结果摘要必须展示实际筛选范围。
2. **P1：比较回答引用错误。** 编号 05 将 `rate` 引用到 `compare_results` 证据，合法字段应为差异字段；原始比例须引用各自的 `query_metric` 证据。宿主正确拒绝，但用户只收到失败。应在输出前明确工具与可引用字段的对应，必要时提供一次受预算约束的纠正机会，不放宽核验。
3. **P1：上下文参数纠正与终验不一致。** 编号 09 首次 `inspect_context` 错传活动域 case/metric，第二次改成合法主上下文后，网关允许继续查询。最终 `Host.turn` 仍要求调用列表第一项必须成功，造成已纠正的流程失败。应统一前置准入与最终核验规则：成功取得本轮上下文前不可进入业务工具；有限参数纠正需要有一致的终验契约。
4. **P1：无关请求的本地分流覆盖不足。** “天气”可以零请求拒绝，“讲笑话”仍进入模型并调用上下文工具。需要扩充常见通用意图的低成本路由并测试变体，同时保留业务自由表达入口，不能以问题示例白名单解决。不能承诺任意自然语言无关问题都可零 token 完美分类。
5. **P2：首次计算耗时和对话成本。** 第一条指标查询约 206 秒，同会话追问约 16 秒；需分析本地首次构建与可复用缓存。群组追问用了 5 次模型请求；继续审查重复检索和上下文体积。每个会话还有累计 12 次模型请求上限，长对话可用性需要单独验收。
